# PR fixer: an agent takes pr-doctor's needs-person repairs

**Goal.** When pr-doctor cannot resolve a queued PR's conflict with main, an agent repairs it with no person involved. Today the PR keeper files a P1 repair bead (external ref `gh-pr-<n>-<head>`) and nothing starts work on it; only a Cookie cycle would, and Cookie is paused. That gap left #384 dequeued for 6h43m on 2026-11-09.

**Architecture.** It keeps the keeper/fixer split from the Fleet Keeper design (ENDURANCE `reports/multi-agent-workflow-mgmt/`, Component 2) and the Step 3 plan's package 3F ("one claimed agent in an isolated workspace with bounded time/resources; return source proof and a handoff to the native reviewer/merger").
The keeper stays mechanical and runs in GitHub Actions; it files the bead.
The fixer is a repo-owned runner, `scripts/dev/pr-fixer.mjs`, run by a systemd user timer on a VM.
Each run does one pass:

1. It takes a host lock, pulls the queue (`bd dolt pull`) and lists open `gh-pr-*` beads.
2. It decides each bead from the PR's GitHub state.
   It closes beads whose PR merged or closed.
   It skips held, skipped, fork and exhausted beads, and beads another actor claimed.
   It repairs at most one PR that still conflicts.
3. It claims the bead as actor `pr-fixer` and syncs.
4. It makes a fresh detached worktree at the PR head and starts `git merge origin/main`.
5. It runs `codex exec` (or `claude -p`) once, with `scripts/dev/pr-fixer/prompt.md`, a time limit and a process-group kill.
   The agent runs in a bubblewrap sandbox that hides the host's credential files (probed before each claim), with no GitHub credential in its environment.
6. It verifies the result itself:
   - nothing is unmerged and the tree is clean;
   - the new HEAD descends from both the PR head and main;
   - no conflict markers remain;
   - HEAD merges cleanly with main;
   - the privacy scan passes;
   - the agent's report says its focused checks passed;
   - `codex exec review --base <main>` reports no P1.
7. It checks the PR head has not moved, then pushes without force.
   It adds a marked repair note to the PR body, which must still pass `checkPrOwner`.
   It runs `scripts/dev/queue-pr.mjs <n> --head <sha>`.
8. It records the outcome on the bead and syncs.
   On success the bead stays `in_progress` with the pushed SHA, and a later pass closes it once the PR merges ("Close only what is on main").
   On failure the claim is released, the attempt is counted and the reason appended.
   After the second failure the bead gets `fixer-exhausted` and stays open at P1 for a worker.

**Tech stack.** Node 24 (no dependencies); git, gh, bd, codex/claude on the host.
**Sources.** `scripts/pr-keeper.mjs` (`repairRef`, `repairBeadArgs`, `repairsToFile`), `scripts/dev/queue-pr.mjs`, `scripts/pr-owner.mjs`, `worker-contract.json`, remote-worker's no-push rule for the agent inside `codex exec`, the fleet beacon's systemd user unit pattern.

## Design challenge

- **Challenger:** this session (claude, brauser-conflict-fixer), arguing the alternatives before task 1. Afterwards `codex exec review` checked the finished change.
- **Alternative 1: add a "repair bead" mode to the remote-worker cycle driver** (it already drains `assigned` P1 beads, has a red-PR repair cycle and keeps the agent from pushing).
  **Outcome: kept the plan.**
  Drivers since v0.3.12 update themselves from the shared repo's newest release tag, so any scaffold release reaches the running workers, which this task must not change.
  The scaffold is also a concurrently edited bash file with a 50-minute suite.
  The cycle model (ideate, build, publish a new PR) is also the wrong shape for "push one merge to someone else's branch".
- **Alternative 2: run the fixer inside GitHub Actions right after the keeper** (no host to manage).
  **Outcome: rejected.**
  An agent with full access, given repository write credentials on a hosted runner, needs a model API key as a repository secret.
  It would also run on every keeper trigger, with no single-flight lock across runners.
  The plan's host choice (a VM) keeps the agent outside the repository's secret scope.
- **Alternative 3 (safer): the agent only proposes a patch and a person applies it.**
  **Outcome: rejected.**
  That breaks the "no human in the loop" principle.
  The runner's own verification, the codex review, CI and Mergify are the gates instead, as for every other session.
- **Adopted from the codex review (P1s):** the agent runs as the same user, so environment stripping alone left the token file readable; a bubblewrap sandbox now masks the secret paths, and a probe refuses the pass if they are readable. The fixer also skips, and refuses to push to, a PR its owner took out of the queue.
- **Adopted from the challenge:** the runner, not the agent, holds the push credential and does every GitHub write (as Cookie's driver does).
  Pushes are never forced and happen only if the PR head is unchanged, so a live owner's push always wins.
