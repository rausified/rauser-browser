## 2026-11-09 — Gate a dependent crate's compile check on its dependency's paths too, or run it unconditionally

Change: when a cheap compile-only check exists because crate B only depends on crate A (no code of its own worth testing, like `adapter-templates/fuzz`), do not gate that check on changes to B's own path. Either gate it on A's paths as well, or — when the check is cheap enough (a `cargo check`, not a full build) — skip the gating entirely and run it unconditionally for every code change, in whichever job already runs for every code change.

Why: `scripts/ci-macos.mjs`'s `MACOS_PATHS` listed `adapter-templates/fuzz/` to send a change to the slow, conditional macOS job, on the reasoning that only a change to the fuzz crate itself needed checking. But the fuzz crate's only purpose is compiling against `adapter-templates`'s own types, so the change that actually breaks it is almost always in `adapter-templates/src`, a path the classifier (correctly, for every other purpose) does not send to macOS. #379 broke `match_title.rs` by changing `TitleMatch.title`'s type in the engine; Windows, Codex and every local gate passed, and only the macOS job, which most PRs skip, caught it — after the PR had already queued (brwr-nu0m). Fixed by moving the check into its own ubuntu job that runs unconditionally for every code change (same gating as the `Accessibility` job), and adding it to `npm run gate:adapter`'s steps for the inputs that already run the engine's own tests.

Where: `.github/workflows/ci.yml` (new `fuzz-check` job), `.github/workflows/build-os.yml` (removed the macOS-only step), `scripts/ci-macos.mjs` (`MACOS_PATHS`), `scripts/gate-adapter.mjs`.
