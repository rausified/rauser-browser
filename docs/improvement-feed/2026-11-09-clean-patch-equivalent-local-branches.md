## 2026-11-09 — Clean up patch-equivalent local branches, bundling before deleting

Change: Give `scripts/dev/worktree-hygiene` a `--branches` mode for local branches that have no worktree. A branch whose every commit is already on `origin/main` by patch (`git cherry origin/main <branch>` prints no `+` line) counts as merged even when `git branch --merged` disagrees, so delete it. For a branch that still holds unique commits, list it (unique and total commit counts, last commit date, whether a remote copy exists) and, with `--apply --bundle PATH`, write all of them to one `git bundle`, verify the bundle's heads, and only then `git branch -D` them. Never delete a remote branch. When the worktree check keeps a worktree because a process holds it, print that process's pid, command and cwd, and re-check that the pid still exists before reporting it.

Why: On 2026-11-09 the main checkout held 14 stale local branches with no worktree. `git branch --merged` found only 3 of them. Two more (`integrate-cookie-2026-11-05`/`-06`) were squash-merged copies with no unique change, which `git cherry` showed as 0/1. The other 9 (`backup/*`, `probe/lanec-*`, two old `fix/*`) were 2 weeks old. They were cleaned up by hand: bundled to `~/Backups/rauser-browser-stale-local-branches-2026-11-09.bundle`, verified, then deleted. Mergify's queue squash-merges and rebase-merges, so commit-ancestry checks will miss more branches over time. On 2026-11-02, worktree-hygiene's process check also reported pid 11131 as holding two worktrees after that process had exited, which held up two removals until the pid was re-checked by hand.

Where: `scripts/dev/worktree-hygiene` and its tests under `scripts/tests/`, plus the hygiene line in `AGENTS.md` "PR ownership and handoff".
