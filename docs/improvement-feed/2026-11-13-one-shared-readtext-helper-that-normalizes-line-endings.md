## 2026-11-13 — One shared readText() helper that normalizes line endings

Change: add one small module, for example `scripts/text.mjs` exporting `readText(path)` (UTF-8, every `\r\n` turned into `\n`) and `writeLike(path, text, original)` (writes `text` in `original`'s line ending), plus a Python twin `read_text()` in `scripts/text_io.py`. Use them in every repo script and test that reads or rewrites checkout text, and have `scripts/check-crlf-reads.mjs` accept a `readText(` call as normalized, so the lint points authors at the helper instead of asking for a `.replace` or a `crlf-ok` comment at each site.
Why: Windows CI checks out with CRLF, and each new script reimplements the normalization or forgets it. The 2026-11-11 delay-fix batch hit its fourth CRLF bug with #456; the ones on record here are #377 (a rename guard that read source text raw, which led to `check-crlf-reads.mjs`), the pr-hygiene sparse-checkout guard (6c91ffc, normalizing `pr-hygiene.yml` before parsing), and #456, where `generate-current-state.test.mjs` matched a `\n`-anchored regex against a CRLF AGENTS.md and failed only on Windows. The fix in #456 also had to keep a generator's writes and the merge driver's spliced lines in the file's own line ending, a second half that a read-only helper alone misses, hence `writeLike`.
Where: a new `scripts/text.mjs` (and Python twin); callers in `scripts/*.mjs`, `scripts/tests/*.mjs`, `scripts/generate-current-state.mjs`, `scripts/sentence-lines.mjs`, `scripts/merge-generated.mjs`; the allowlist in `scripts/check-crlf-reads.mjs`; a line in AGENTS.md "Local checks".
