## 2026-11-09 — Fingerprint adapter documents by their content, not their Debug text

Change: Replace `adapters_fingerprint` in `host/src/index/mod.rs`, which hashes `format!("{document:?}")`, with a hash of a canonical serialization of the adapter document as the user wrote it (JSON with sorted keys). Pin it with a test that adds a field to `Adapter` and checks an unchanged document keeps its fingerprint. Why: on 2026-11-09 adding the optional `generic_titles` field to the engine's `Adapter` struct changed the derived `Debug` text of every document, including ones that never use the key. Six `index::tests::migration` tests failed, and an upgraded host would have marked every user's index as built under another document and re-derived its adapter-dependent files. The fix in this change writes `Debug` for `Adapter` by hand so an empty `generic_titles` prints as before. That works, but every later engine field would need the same care, and nothing reminds the author until the migration fixture breaks. Where: `host/src/index/mod.rs` (`adapters_fingerprint`), `adapter-templates/src/document.rs` (`impl Debug for Adapter`).
- Review 2026-11-12: **Keep.** Hash adapter contents rather than Rust debug formatting; adding an unused field changed all fingerprints and triggered needless index rebuilds.
