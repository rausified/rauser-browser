## 2026-11-09 — Check which states a history guard sees before choosing a fix

Change: before settling a re-key fix in the host's history guard, list every path that reaches the same end state (adding to live adapters, re-adding retired ones, in one save or two), and check which of them the guard actually inspects. Why: brwr-qps4's first ruling was to refuse a container's re-key of retired contained routes, but `refuse_rekeyed_routes` only compares against retired and removed contracts. Adding Splunk apps to live dashboards re-keyed the same URLs untouched, and the refusal would also have blocked every re-add after a removal. Preventing the state (a dashboard live without apps) closed all of these paths with one check. Where: `host/src/config.rs` (`refuse_rekeyed_routes`, `refuse_new_container_first_gap`); AGENTS.md could ask for this list in any PR that changes the history guard.
